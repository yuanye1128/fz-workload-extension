# FZ 工单工作量统计 Chrome 扩展

用于统计 `https://kb.fzyun.net` 工单系统中，某个月由本人把工单状态改为“待测试”或“已完成”的工作量。

## 统计规则

- 只统计工单历史记录里的状态变更。
- 默认按当前登录用户统计，无需手工填写操作者姓名。
- 状态命中以下任意一个即计入：
  - `待测试`
  - `已完成`
- 同一个工单当月多次命中，只计 1 个工作量。
- 如果同一个工单既由本人改成“待测试”，又由本人改成“已完成”，仍然只计 1 个。

## 安装方式

1. 打开 Chrome。
2. 访问 `chrome://extensions/`。
3. 打开右上角“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 选择本目录：

   ```text
   tools/kb-workload-extension
   ```

## 使用方式

1. 先在浏览器里登录知识库。
2. 打开知识库个人活动页面。

3. 点击 Chrome 工具栏里的“FZ 工单工作量统计”扩展图标。
4. 点击“打开统计面板”。
5. 在页面右下角面板里选择：
   - 统计月份
   - 扫描范围
6. 点击“开始统计”。
7. 统计完成后可以点击“导出HTML报表”。

## 扫描范围

- `仅当前列表页`：只扫描当前列表页里出现的工单。
- `当前筛选的全部分页`：从当前筛选条件出发，按“下一页”逐页扫描。扫描会根据列表里的更新时间自动停止，例如选择 `2026-04` 时，会扫描更新时间不早于 `2026-04-01` 的工单；当整页工单都早于 `2026-04-01` 时停止继续翻页。

建议列表按更新时间倒序排序，例如：

```text
sort=priority:desc,updated_on:desc
```

## 实现说明

扩展不会保存账号密码，也不会请求外部服务。  
它在 `kb.fzyun.net` 页面内运行，复用当前浏览器登录态，通过 `fetch(..., credentials: "include")` 拉取列表页和详情页 HTML。

主要文件：

| 文件 | 作用 |
|---|---|
| `manifest.json` | Chrome 扩展声明 |
| `popup.html` / `popup.js` | 工具栏弹窗入口 |
| `content.js` | 注入页面的统计逻辑 |
| `content.css` | 页面右下角统计面板样式 |

## 调试建议

如果统计结果不准，优先检查：

1. 工单详情页历史记录里，操作者显示名是否和面板里填写的一致。
2. 历史记录文本是否包含“待测试”或“已完成”。
3. 历史记录日期是否能被识别为 `YYYY-MM-DD` 或 `YYYY年M月D日`。
4. 列表页的工单链接是否是 `/issues/工单ID` 格式。

可以在 Chrome 开发者工具 Console 中搜索日志前缀：

```text
[KB Workload]
```

## 已知限制

- 第一版依赖页面 HTML 结构和历史记录文本。如果知识库页面改版，可能需要调整 `content.js` 里的解析器。
- 如果历史记录只显示相对时间（例如“3 天前”），当前版本无法准确归属月份。
- “全部分页”依赖列表页中的工单更新时间判断停止位置。如果列表未按更新时间倒序排序，可能会提前停止或多扫页面。
- 如果分页是前端异步加载且 HTML 中没有“下一页”链接，需要单独适配接口。
